# 版本部署变更说明 v0.1.4

- 版本：`0.1.4`（`manifest.json` / `package.json` / `backend/Cargo.toml` 三处一致）
- 产物：`release/com.mjj3610.mail-0.1.4-windows-x64.dbxp`
- 变更性质：**安全修复 + 合规修复**，无数据结构变更，可直接覆盖安装
- 影响范围：前端（正文渲染顺序、撰写器净化）、后端（图片代理出网校验）、随包许可文件

## 1. 安全修复（P1）：回复/转发引用块未净化

**问题**

阅读器路径是对的：`Reader.tsx` 先 `prepareMailBody`（DOMPurify 白名单）再 `dangerouslySetInnerHTML`。
但撰写器是第二个注入点，此前没有覆盖：

- `stores/composer.ts` 的 `quoteBlock()` 把后端 MIME 解析出的 `detail.htmlBody` **原样**拼进引用块
  （`mime.rs` 只做 cid 内联，不做净化），随后 `openDraft()` 又把 `draft.bodyHtml` 直接灌进撰写器；
- `components/Composer.tsx` 用 `element.innerHTML = composer.html` 写入 `contentEditable` 容器。

宿主的 workbench iframe 是 `sandbox="allow-scripts"` + `script-src 'unsafe-inline'`，
所以 `<img src=x onerror="…">` 这类内联事件处理器会真的执行；执行后可通过
`window.dbxPlugin.invoke` 调到 sidecar 的方法（任意读文件、写附件、读缓存邮件、以用户身份发信）。

**修复**

净化收口到一处，三层都走同一个函数：

| 位置 | 改动 |
| --- | --- |
| `src/lib/html.ts` | 新增 `sanitizeComposerHtml()`；白名单常量 `FORBID_TAGS` / `FORBID_ATTR` / `COMPOSER_FORBID_TAGS` 与阅读器共用（原来是一份硬编码数组，两套配置容易漂移） |
| `src/stores/composer.ts` | `quoteBlock()` 对 `detail.htmlBody` 调用 `sanitizeComposerHtml`；`openDraft()` 对 `draft.bodyHtml` 同样处理（旧版本草稿、外部导入草稿一律按不可信内容对待） |
| `src/components/Composer.tsx` | 赋值前最后一道 `sanitizeComposerHtml(composer.html)`，将来新增入口也不会漏 |

撰写器配置比阅读器更严：额外禁掉 `svg` / `math` / `noscript` / `template` / `audio` / `video` / `source` / `track`。
引用块内的远程图片（含相对路径 `src="x"`）一律换成 `[图片：alt]` 文字占位，`data:` 内联图（cid）保留。

**新增回归**：`scripts/sanitize-check.mjs`（`npm run sanitize-check`）。
样例数据是 `?demo=1&evil=1` 挂的恶意邮件，载荷包括 `<img onerror>`、`javascript:` 链接、`<iframe>`、
`<svg onload>`、`<script>`、`<form>`、CSS 里的远程 `url()`；每条载荷都会写 `window.__dbxXss`，
断言「标记没有出现」而不是「标签被删了几种」，避免只改标签名就绕过。

## 2. 安全修复（P2）：图片代理的 SSRF 重定向绕过

**问题**

`main.rs` 的 `mail_fetch_image` 只对**首个 URL** 做 `ensure_public_host`，
随后用 `reqwest::redirect::Policy::limited(3)` 跟随跳转——302 跳到 `http://127.0.0.1:8080/`
即可绕过白名单。此外原实现漏掉了 CGNAT（100.64/10）、保留段（240/4）、
IPv4-mapped IPv6（`::ffff:127.0.0.1`）等地址。

**修复**

新增 `backend/src/net_guard.rs`（含 7 项单测），统一负责出网判定：

- `check_host()`：本机/局域网后缀（`localhost`、`.local`、`.internal`、`.home.arpa`）直接拒；
  主机名是 IP 字面量时不走 DNS；解析出的**每一个**地址都必须是公网地址（同一域名混回内网即整体拒绝）。
- `ip_is_blocked()`：IPv4 补 `0/8`、`100.64/10`、`192.0.0/24`、`192.0.2/24`、`198.18/15`、
  `198.51.100/24`、`203.0.113/24`、`240/4`；IPv6 先把 `::ffff:a.b.c.d` 与已废弃的
  IPv4-compatible `::a.b.c.d` 还原成 v4 再判，另挡 `fc00::/7`、`fe80::/10`、`fec0::/10`、
  `2001:db8::/32`、`64:ff9b::/96`。
- `redirect_policy()`：`Policy::custom` 逐跳复核，超过 3 跳或目标被拒即 `attempt.error()`。

**未覆盖**：DNS rebinding（首次解析通过、连接时换成内网 IP）。彻底解决需要解析后 pin IP 连接，
已在该模块文档注释里标注为后续加固项。

**顺带修复（P3 建议）**：远程资源改为**挂载前**占位。`prepareMailBody` 在返回 HTML 之前就把
`<img src>` 换成透明像素（原地址存 `data-remote`，供「显示图片」恢复）、清掉内联 `style` 与
`<table background>` 里的 `url()`；`scopeCss` 把 `<style>` 中的远程 `url()` 置为 `none`。
此前 `applyImagePolicy` 在挂载后才跑，赋值到 `innerHTML` 的那一瞬间就已经发出请求了
（真实 IP 与「邮件被打开过」都会暴露）。`sanitize-check` 的控制台断言现在要求零外发请求。

## 3. 合规修复（P2）

**3.1 LICENSE 被改过**

`LICENSE` 第 4 行原为 `Copyright (C) 2025 codexu, https://notegen.top/.`——这是另一个项目的署名，
而 GPL-3.0 明确要求「逐字复制、不得修改」许可证正文。已恢复为 FSF 标准行
`Copyright (C) 2007 Free Software Foundation, Inc. <https://fsf.org/>`，现在与 `licenses/GPL-3.0.txt`
逐字一致（`diff` 无差异）。本插件的版权归属改由新增的 `NOTICE` 承载，README 第 7 节同步说明。

`dbx-plugin.toml` 的 `include` 增加 `NOTICE`，随包分发。

**3.2 第三方许可不全**

- 补充 `urlencoding`、`futures-util`、`async-channel`、`rustls-pki-types`（均为 `Cargo.toml` 直接依赖，
  此前漏登记）。
- **更正**：`webpki-roots` 现行版本（0.26.11 / 1.0.11）的许可证是 **CDLA-Permissive-2.0**，
  不是 MPL-2.0。已按实际声明更正，并补 `licenses/CDLA-Permissive-2.0.txt` 全文。
- 另外用 `Cargo.lock`（257 个包）全量比对，补登此前完全没提的非 MIT/Apache 组件：
  ICU4X 系列（`icu_*` / `zerovec` / `yoke` 等 18 个包，**Unicode-3.0**）、
  `rustls-webpki` / `untrusted`（ISC）、`zlib-rs`（**Zlib**），并按类别补 `licenses/Unicode-3.0.txt`、
  `licenses/Zlib.txt`。
- `THIRD-PARTY-NOTICES.md` 新增「许可证副本索引」与「传递依赖中非 MIT/Apache 的许可证」两节，
  给出「文件 ↔ 许可证 ↔ 组件」的对应关系。

## 7. 部署流程

1. 停止当前运行的插件工作台（关闭「邮件」窗口即可，宿主会结束 sidecar 进程）。
2. 确认没有残留 sidecar：任务管理器里不应再有 `backend.exe`；如仍有，先结束再继续。
   占用端口检查无需执行（本插件不监听任何端口）。
3. 构建（仓库内）：
   ```bash
   npm install
   npm run build                    # 前端单文件 bundle → ui/
   cd backend && cargo build --release && cd ..   # 必须在 backend/ 下，rustup 才会读到 rust-toolchain.toml
   npm run sidecar-check            # 15 项协议冒烟
   npm run sanitize-check           # 13 项注入回归（需先 npm run build）
   npm run pack                     # → release/com.mjj3610.mail-0.1.4-windows-x64.dbxp
   ```
4. 覆盖安装：DBX → 插件 → 从本地文件安装 `com.mjj3610.mail-0.1.4-windows-x64.dbxp`。
5. 校验：
   - 设置页「版本」显示 `0.1.4`；
   - 打开一封 HTML 邮件，正文排版与图片拦截正常（`npm run render-check` 三件套可复跑）；
   - 回复一封 HTML 邮件，引用块里的图片显示为 `[图片]` 占位、正文可编辑；
   - 发件箱可正常投递。
6. 回滚：重新安装 `com.mjj3610.mail-0.1.3-windows-x64.dbxp` 即可。数据库未迁移，0.1.3 可读
   0.1.4 写出的数据（新增内容只有错误文案与许可文件）。
