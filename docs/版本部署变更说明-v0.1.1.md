# 版本部署变更说明 v0.1.1

- 版本：`0.1.1`（`manifest.json` / `package.json` / `backend/Cargo.toml` 三处一致）
- 产物：`release/com.mjj3610.mail-0.1.1-windows-x64.dbxp`
- 目标：`windows-x64`，13 个条目，2.33 MB
- 变更性质：**缺陷修复**，无接口与数据结构变更，可直接覆盖安装

## 1. 修复的问题

用户现场：**账户连接测试通过（IMAP、SMTP 均连通），但点「同步」报错**，且错误集中在文件夹层面。

### 1.1 中文文件夹名未做 modified UTF-7 编码（主因）

IMAP 协议里文件夹名走 **modified UTF-7**（RFC 3501 §5.1.3），服务器只认 `&XfJT0ZAB-` 这类线上编码；原始中文名（「已发送」「草稿箱」「垃圾邮件」）直接发过去会被判为非法名字。v0.1.0 只实现了**解码**（`LIST` 返回 → 界面显示中文），**没有实现编码**，于是：

- `LIST` 正常 → 文件夹能列出来、能入库；
- 随后 `STATUS` / `EXAMINE` / `SELECT` 带上中文名 → 服务器拒绝，同步在第一个文件夹就中断。

修复：

- `backend/src/imap.rs` 新增 `encode_utf7()` / `flush_utf7()`（6 位一组的 UTF-16 → base64 变体，字母表第 62/63 位是 `+` 与 `,`；`&` 写作 `&-`；纯 ASCII 名字原样返回）。
- **存储与显示仍用解码后的可读名字**，只在发命令前编码：`select`（含 `EXAMINE`）、`status`、`move_message`（`COPY`/`MOVE` 的目标名）、`append`（写「已发送」）。函数签名不变，调用方（`sync.rs`、`compose`、`deliver`）无需改动。

### 1.2 163 / 126 缺少 RFC 2971 `ID` 报到（次因）

网易系邮箱要求客户端在 `LOGIN` 后先发 `ID`（`name` / `version` / `vendor`），否则 `SELECT` 返回 `NO Unsafe Login`——表现同样是「连接正常、同步失败」。

修复：`ImapClient::open()` 在读取能力后，若能力列表含 `ID` 即发送报到（带超时，失败不阻断）。

### 1.3 编码兜底（顺带加固）

少数服务器返回的是**原始 UTF-8** 文件夹名、不认 mUTF-7。为避免「修好一类、弄坏另一类」：

- `select` / `status` / `append` / `move_message` 先按编码名发送，失败且与原名不同时**退回原名重试一次**；
- 重试仅针对服务器拒绝，`append` 遇到**超时**不重试，避免同一封邮件写两次。

### 1.4 版本号漂移

`backend/src/main.rs` 里 `PLUGIN_VERSION` 原本硬编码 `"0.1.0"`，与 `Cargo.toml` 各自维护，升版本时必然漂移，握手校验会直接失败。改为 `env!("CARGO_PKG_VERSION")`，`scripts/sidecar-check.mjs` 也改成从 `manifest.json` 读期望值。

## 3. 升级步骤

1. 关闭当前邮件工作台页面（避免占用 `backend.exe`）；
2. 用新包覆盖安装：`release/com.mjj3610.mail-0.1.1-windows-x64.dbxp`；
3. 重新打开工作台 → 设置里确认版本为 **0.1.1**；
4. 对出问题的账户点一次「同步」。若仍报错，错误信息已带文件夹名前缀（形如 `已发送：选择文件夹「已发送」失败：…`），把该行原文反馈即可精准定位。

数据无需迁移：SQLite 表结构与 `0.1.0` 完全一致，本地缓存、草稿、发件箱、附件目录沿用原位置。

## 4. 回滚

重新安装 `release/com.mjj3610.mail-0.1.0-windows-x64.dbxp` 即可。本地数据库兼容（无新列、无新表）。
