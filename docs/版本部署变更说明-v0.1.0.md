## 1. 交付内容

### 1.1 邮件能力（对齐 Penguin Mail 的邮件功能）

| 能力 | 实现要点 |
| --- | --- |
| 多账户 IMAP/SMTP | 8 个服务商预设按域名自动补全 host/port/加密方式；`user@gmail.com` 这种用户名与邮箱不同的情况可单独填 `username` |
| 增量同步 | `SELECT` 后比对 `UIDVALIDITY`：变了就清空该文件夹的本地头重新拉；没变按 `last_uid` 用 `UID FETCH (last+1):*` 拉新 |
| 旗标双向 | 本地改动先写 `pending_flags`（含 `seen/flagged/answered` 的期望值），同步时先 `STORE` 回写再清空，避免「服务器旧值把本地新值冲掉」 |
| 会话聚合 | `thread_key` 依次取 `References[0]` → `In-Reply-To` → `Message-ID` → `s:<sha256 前 18 位>`；SQL 侧按 key 分组并聚合未读数、星标、附件、参与者 |
| 阅读 | 原始 `.eml` 首次按需 `UID FETCH BODY.PEEK[]` 落盘到 `raw/<account>/<mailbox>/<key>.eml`，之后离线可读；正文 `cid:` 内联图转 data URL（8 MB / 5 MB 预算） |
| 远程图片 | 默认拦截；点「显示图片」由 Sidecar 用 `reqwest` 取回并转 data URL；代理层做协议白名单 + 拒绝环回/内网/链路本地地址 + 10 MB 上限 |
| 撰写 | `mail-builder` 组 MIME，`lettre` 发信；附件 25 MB/个、40 MB 总量；正文纯 HTML + 可选纯文本兜底 |
| 草稿 | 4.5 秒静默自动保存；发送成功后按 `draftId` 删除 |
| 发件箱 | 一切发送先入 `outbox`（`status=queued`）；「立即发送」也留 `undoDelay + 0.8s` 的撤销窗口；后台线程每 2 秒取 `scheduled_at <= now` 的队列投递；失败 `attempts+1` 并记录 `error` |
| 归档/删除/移动 | 优先 `MOVE`（RFC 6851），不支持时 `COPY` + `\Deleted` + `UID EXPUNGE` |
| `.eml` 导入导出 | 导出按「主题前 40 字-时间戳.eml」命名，同名加 ` (2)`；导入走同一套解析器，本地建档并写正文/附件缓存 |
| 快捷键 | `c` 写、`r` 回复、`a` 回复全部、`f` 转发、`j/k` 上下封、`e` 存档、`#` 删除、`s` 星标、`u` 未读、`/` 搜索、`Esc` 关闭、`Ctrl/⌘+Enter` 发送 |

## 2. 接口约定（DBX Plugin Protocol v1）

- 传输：JSON-RPC 2.0，**逐行** stdin/stdout；一行一个对象。
- 握手：宿主发 `plugin/initialize`，Sidecar 回
  `{ protocolVersion: 1, capabilities: {...}, plugin: { id: "com.mjj3610.mail", version: "0.1.0" } }`。
  **版本号必须与 `manifest.json` 完全一致**，否则宿主拒绝加载。
- 错误：`{ code, message, data? }`；`-32601` 未实现方法、`-32602` 参数非法、`-32603` 内部错误。
- 超时：前端 `call()` 默认 20 s，网络类 110 s，发送 120 s；宿主 `invoke` 未提供时抛错（演示模式除外）。

| 分组 | 方法 |
| --- | --- |
| 基础 | `ping`、`app/bootstrap`、`app/info` |
| 账户 | `account/presets`、`account/list`、`account/add`、`account/update`、`account/remove`、`account/test`、`account/discover` |
| 文件夹 | `mailbox/list` |
| 同步 | `sync/now`、`mailbox/sync`、`sync/status` |
| 列表与阅读 | `mail/list`、`mail/thread`、`mail/open`、`mail/flags`、`mail/move`、`mail/part`、`mail/export`、`mail/import`、`mail/fetchImage` |

字段命名统一 `camelCase`（Rust 侧 `#[serde(rename_all = "camelCase")]`）。

### 2.2 清单权限

`manifest.json` 的 `permissions` 为**空数组**。本插件不需要任何 Host API 权限：

- 宿主只接受 `host.network:<url>` 形式的网络权限，写 `host.copy` 这类通用能力会被判定为
  `Unsupported plugin Host API permission`，插件直接加载失败；
- 剪贴板、文件系统、网络全部由 Sidecar 或页面自身完成，不经过 Host API。

`src/lib/bridge.ts` 的 `copyText()` 因此按「宿主能力（若将来声明）→ `navigator.clipboard` →
隐藏 textarea + `execCommand` 」逐级降级，缺少权限时不报错、不影响其它功能。

### 2.3 文件系统边界

页面运行在 `connect-src 'none'` 的沙箱里，**没有** FS / 网络能力，因此：

| 需求 | 走的方法 | 说明 |
| --- | --- | --- |
| 选目录 | `fs/dirs` | 返回 `path / parent / entries(仅目录) / roots / shortcuts / writable`，自绘选择器 |
| 选文件 | `fs/files` | 返回 `{name, path, size, mtime}` |
| 读本地文件 | `fs/readFile` | 返回 base64 + 推断 MIME |
| 撰写器附件 | `fs/saveUpload` | 前端读 `File` → base64 → 落 `<数据目录>/tmp/`，只把路径记进草稿 |
| 保存邮件附件 | `fs/saveAttachment` | 按 `messageId + 部件索引` 从原始 `.eml` 解出，写到选定目录，同名加序号 |
| 导出 `.eml` | `mail/export` | 同上，返回实际写入路径列表 |
| 原始邮件缓存 | 内部 | `raw/<account>/<mailbox>/<key>.eml`，不暴露给前端 |

## 4. 关键实现决策

1. **立即发送也入队。** 统一「撤销窗口 / 失败重试 / 离线排队」三条路径，代价是发送成功到真正
   `SMTP DATA` 之间最多有 `undoDelay` 的延迟；用户点撤销即把 `status` 改为 `canceled`。
2. **旗标用 pending 表而不是直接覆盖。** IMAP 的 `\Seen` 会被服务器上的其它客户端同时改，
   先记期望值再回写、成功即清空，离线时也不会丢。
3. **附件不落库。** `attachments` 只存元数据，字节按需从原始 `.eml` 解出；SQLite 不会因附件膨胀，
   代价是原始邮件被外部删除后附件不可取（已在 README「已知限制」标注）。
4. **远程图片走后端代理。** 即便宿主 CSP 允许，直连 `<img src="https://…">` 也会把打开动作与 IP
   暴露给发件人；代理层同时做了 SSRF 白名单，避免被邮件正文当作内网探针。
5. **深色模式下摘掉正文颜色声明。** 多数邮件把文字写成固定深色，直接放深色底上会看不见；
   `adaptForDark()` 只移除 `color` / `background(-color)`，保留字号、间距、边框，并把浅色边框换成主题色。
6. **单文件 bundle。** 宿主只内联 `<script src>` 与样式，拆包即白屏：`cssCodeSplit:false`、
   `modulePreload:false`、`assetsInlineLimit` 取最大值、`inlineDynamicImports:true`。
7. **自绘目录选择器。** 沙箱里没有 `showDirectoryPicker`/`webkitdirectory` 的可靠路径返回，
   统一走 `fs/dirs` + `fs/files`，这样 Windows 盘符、Linux 根目录、快捷位置都能正确展示。

## 5. 构建与打包

```bash
# 1) 前端（单文件 bundle → ui/）
npm install
npm run build

# 2) Sidecar（backend/rust-toolchain.toml 已固定 gnu，MSVC 的 link.exe 常被 Git 的 link 抢占）
cargo build --release --manifest-path backend/Cargo.toml

# 3) 协议冒烟（15 项：握手 / 版本一致 / 设置持久化 / 目录 / 列表 / 未知方法）
node scripts/sidecar-check.mjs --bin backend/target/release/backend.exe

# 4) 打包
npm run pack            # = node scripts/package.mjs
```

**关于打包方式。** 官方 `dbx-plugin package` 会以 `\\?\` 前缀路径调用 cargo 且强制 `--locked`；
本机没有 MSVC Build Tools、只能用 GNU 工具链，MinGW 的 ld 无法处理该前缀
（`cannot find \\symbols.o`），CLI 也没有「跳过编译」的开关。因此 `scripts/package.mjs`
按 CLI 的产物格式自行打包，额外产出 `[[patch.unused]]` 的锁定修正不需要了——打包器不碰 Cargo 配置：

- 目录布局与 CLI 一致：`manifest.json`、`ui/**`、`assets/**`、`bin/<target>/backend.exe`、
  `LICENSE`、`THIRD-PARTY-NOTICES.md`、`licenses/**`；
- `manifest.json` 的 `entrypoints.backend.executable` 改写为 `bin/windows-x64/backend.exe`；
- 生成 `checksums.json`（`algorithm: sha256` + 除自身外全部文件的摘要）；
- 旁边写 `<id>-<version>-<target>.artifact.json`（`target/url/sha256/size`）；
- zip 条目为 DOS 属性 + deflate，与 CLI 产物逐项对齐（13 个条目）。

装有 MSVC Build Tools 的机器上 `npm run pack:cli` 可直接使用官方打包器。

产物：`release/com.mjj3610.mail-0.1.0-windows-x64.dbxp`（约 2.3 MB，13 个条目，
`checksums.json` 与实际内容逐项一致），摘要与体积同时写在同名 `.artifact.json` 里。

### 5.2 部署步骤

1. DBX → 插件管理 → 安装本地插件，选择 `.dbxp`。
2. 打开「邮件」工作台；首次进入显示「开始使用邮件」。
3. 添加账户：填邮箱与授权码（Gmail/QQ/163 等需应用专用密码），服务商自动识别后可「测试连接」。
4. 保存后自动同步收件箱；`syncScope=all` 时同步全部文件夹。
5. 设置 → 同步：可改同步间隔、首次同步邮件数、撤销发送窗口。

### 5.3 升级与回滚

- 本版本为首次发布，无迁移负担；后续版本按 `PRAGMA user_version` 递增迁移，不删表、不改列语义。
- 回滚：卸载插件不会删除数据目录（`<DBX 数据目录>/plugins/com.mjj3610.mail`），重装低版本时
  旧版本会忽略新增列；若做过不兼容迁移，先备份 `mail.db`。

## 6. 已知限制与后续计划

| 项 | 现状 | 计划 |
| --- | --- | --- |
| POP3 / JMAP / Exchange | 未支持 | 0.2.x 视需要加 JMAP |

| 会话聚合 | 依赖 `References`/`In-Reply-To` | 可加「同主题 + 时间窗」兜底 |
| 日历 | `.ics` 仅作附件展示 | 后续接日历视图 |
| 离线写信队列的加密 | 正文以明文存 `outbox` | 可选 SQLCipher 或正文加密 |
| 多语言 | 简中 / 英 | 预留泰 / 韩 / 日（字典结构已按此设计） |
